# 四象限 · 设计与边界

已在编码前阅读本机 frontend-design 与 feature-architecture SKILL.md（2026-10-08）。

## 第一遍：视觉方案

核心意象是可反复整理的四格工作纸。整个窗口就是任务矩阵，无介绍、统计、导航与面板包装。

色彩：纸白 `#F8F7F4`，墨灰 `#30312F`，次级灰 `#777973`，细线 `#DEDED7`，朱灰 `#A66C60`，鼠尾草 `#708474`。另两象限使用低饱和蓝灰与石灰色，仅标记标题及拖放目标。

字体：本地 Geist variable（SIL OFL 1.1）承担英文、数字与拉丁标点；系统 PingFang SC 承担中文。正文 15px / 24px、标题 17px / 25px、提示 12px / 20px。不用整页等宽字、不用展示衬线，也不靠夸张字距制造气质。

研究：Claude Code 官方介绍展示 Terminal、IDE、Desktop 等多个界面形态，并未指定统一的官方 UI 字体。借鉴其开发工具排版的清晰、紧凑与文本优先气质，不声称 Geist 是 Claude Code 的官方字体。
参考 https://code.claude.com/docs/en/overview 与 https://github.com/vercel/geist-font 。

布局：主界面始终 2×2，左右与上下等分，只有两条中央分割线；标题、任务正文均左对齐。每个象限独立滚动，标题与低调加号固定。macOS 原生红黄绿按钮与窗口缩放保留。

```
┌────────────── 原生窗口标题栏 ──────────────┐
│  重要且紧急             + │ 重要不紧急             + │
│  □ 任务                   │ □ 任务                    │
│                           │                           │
├───────────────────────────┼───────────────────────────┤
│  紧急不重要             + │ 不重要不紧急           + │
│  □ 任务                   │ 点击 + 添加任务           │
└───────────────────────────┴───────────────────────────┘
```

原则：把设计力度用于四格的比例、行间节奏和原位操作。图标只承载动作；任务本身是唯一内容。完成态保留在原顺序，不另设归档列表。拖动手柄只在悬停或键盘焦点时出现。

## 第二遍：编码前审视

暖白是用户明确要求，保留；去掉通常伴随它的陶土大色块、展示衬线、卡片阴影与欢迎文案。四格不能编号，因为它们不是步骤。去掉任务数量与说明性副标题，因为本产品不需要统计或附加层级。空状态只说明添加动作。

深色使用暖石墨底，不染整块象限；跟随 prefers-color-scheme。交互动画只响应添加、完成、拖动，遵守 reduced-motion。

## 实现职责

- `src/domain/tasks.ts`：任务结构、标题校验、移动与排序规则。
- `src/storage/`：原生命令适配与串行保存队列；浏览器预览使用单独存储，非正式应用数据。
- `src/components/`：任务行、原位编辑、象限布局与拖放展示。
- `src-tauri/src/storage.rs`：本机 SQLite、事务写入、结构校验、故障报告。
- `src-tauri/src/lib.rs`：窗口生命周期、关闭前等待编辑提交与保存完成。

正式数据位于 macOS Application Support 下的应用专用目录，使用 SQLite 完整同步事务；不依赖浏览器缓存、服务器或网络。

## 验收

功能浏览器验证覆盖新增、中文 IME、编辑、完成/取消完成、删除、跨象限移动、内部排序、重载、两种主题、缩放与长列表。Rust 测试覆盖事务、重开与无效数据保护。最终另运行真正的 .app，检查原生窗口及退出后数据。

## 构建后的复查

已复查空态、有任务的浅色、深色、620×440 紧凑窗口。保留暖白工作纸与中央分割，撤掉了悬停指针后再拍正式截图，避免把瞬时反馈当成静态设计。深色截图等待颜色过渡结束；正文、完成态与细线层级可辨。原生编辑中退出的验证发现菜单退出绕过保存等待，已用统一退出事件与原生退出许可标记修正并现场重开验证。详情见 VERIFICATION.md。

## 悬浮小组件 · 2026-10-09

编码前完整阅读已安装 frontend-design 与 feature-architecture Skill，并核对 Tauri 官方窗口、事件、window-state 文档。

第一遍方案：像摆在桌角的一张小型任务纸，380×360，最小 340×300。仅顶部 44px 可拖动标题与三个轻线图标，下方平衡的 2×2 网格。文字左对齐，标题 11px/18px、任务 12px/19px，英文 Geist、中文系统苹方，数字沿用同一家族的 tabular-nums，不额外引入等宽标签。背景纸白 #F8F7F4，文字 #242521，次级灰 #8B8D88，线 #E3E2DD，悬停 #F2F1ED；小色点使用陶土 #A66C60、鼠尾草 #708474、琥珀 #A18857、灰 #98968C。深色用暖石墨，颜色仅用于定位标记。使用原生窗口圆角及阴影，不用透明毛玻璃。

```
┌ 四格图标 四象限          图钉 打开 隐藏 ┐
│ · 重要且紧急 2    │ · 重要不紧急 1     │
│ ○ 核对交付清单   │ ○ Read & reflect  │
│              +  │               +  │
├─────────────────┼──────────────────┤
│ · 紧急不重要 1   │ · 不重要不紧急 0   │
│ ○ 回复邮件       │ 暂无任务           │
│              +  │               +  │
└─────────────────┴──────────────────┘
```

编码前复审：暖白、四格均为用户明确要求。避免把每格包装成独立卡片；四格共用连续纸面，仅中央分割。任务数量只表示未完成件数，不加入统计。新增入口置于格子底部，任务完成圆圈提供足够点击范围；编辑任务复用原位输入，删除仅悬停出现，小组件不放拖动排序手柄。长标题最多两行，各格独立细滚动条，标题与新增入口固定。默认普通层级，图钉由用户选择置顶；状态用一枚小点与颜色表示，避免多余文字。

动效响应用户操作，140–180ms，完成态淡化与删除线，窗口显示/隐藏使用轻淡出并尊重 reduced-motion。任何保存错误必须可见且可重试。主窗口增加唯一的小组件入口，原生窗口菜单同步提供入口，不另建导航。

架构落位：领域模块定义任务变更；前端 store 负责乐观显示、待提交变更队列和原生事件接收；Rust 存储层在单个 SQLite 事务中把字段变更合并到最新文档，发出带递增 revision 的快照。不让两个窗口分别写完整旧快照。窗口创建、置顶、隐藏、状态恢复与退出协调由原生窗口模块负责。退出须等待所有窗口提交当前编辑并确认保存。

官方参考： https://v2.tauri.app/plugin/window-state/ 、 https://v2.tauri.app/reference/javascript/api/namespaceevent/ 、 https://v2.tauri.app/reference/config/ 。

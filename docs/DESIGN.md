# 四象限 · 设计与边界

当前版本 1.3.2 仅保留主窗口；下方 1.1.0–1.3.1 的小组件方案和复查记录为历史记录，当前窗口与生命周期以文末 1.3.2 节及源码为准。

已在编码前阅读本机 frontend-design 与 feature-architecture SKILL.md（2026-10-08）。

## 第一遍：视觉方案

核心意象是可反复整理的四格工作纸。整个窗口就是任务矩阵，无介绍、统计、导航与面板包装。

色彩：纸白 `#F8F7F4`，墨灰 `#30312F`，次级灰 `#777973`，细线 `#DEDED7`，朱灰 `#A66C60`，鼠尾草 `#708474`。另两象限使用低饱和蓝灰与石灰色，仅标记标题及拖放目标。

字体：本地 Geist variable（SIL OFL 1.1）承担英文、数字与拉丁标点；系统 PingFang SC 承担中文。正文 15px / 24px、标题 17px / 25px、提示 12px / 20px。不用整页等宽字、不用展示衬线，也不靠夸张字距制造气质。

研究：Claude Code 官方介绍展示 Terminal、IDE、Desktop 等多个界面形态，并未指定统一的官方 UI 字体。借鉴其开发工具排版的清晰、紧凑与文本优先气质，不声称 Geist 是 Claude Code 的官方字体。
参考 https://code.claude.com/docs/en/overview 与 https://github.com/vercel/geist-font 。

布局：主界面始终 2×2，左右与上下等分，只有两条中央分割线；标题、任务正文均左对齐。每个象限独立滚动，标题与低调加号固定。macOS 原生红黄绿按钮与窗口缩放保留。

```
┌────────────── 原生窗口标题栏 ──────────────┐
│  重要且紧急             + │ 重要不紧急             + │
│  □ 任务                   │ □ 任务                    │
│                           │                           │
├───────────────────────────┼───────────────────────────┤
│  紧急不重要             + │ 不重要不紧急           + │
│  □ 任务                   │ 点击 + 添加任务           │
└───────────────────────────┴───────────────────────────┘
```

原则：把设计力度用于四格的比例、行间节奏和原位操作。图标只承载动作；任务本身是唯一内容。完成态保留在原顺序，不另设归档列表。拖动手柄只在悬停或键盘焦点时出现。

## 第二遍：编码前审视

暖白是用户明确要求，保留；去掉通常伴随它的陶土大色块、展示衬线、卡片阴影与欢迎文案。四格不能编号，因为它们不是步骤。去掉任务数量与说明性副标题，因为本产品不需要统计或附加层级。空状态只说明添加动作。

深色使用暖石墨底，不染整块象限；跟随 prefers-color-scheme。交互动画只响应添加、完成、拖动，遵守 reduced-motion。

## 实现职责

- `src/domain/tasks.ts`：任务结构、标题校验、移动与排序规则。
- `src/storage/`：原生命令适配与串行保存队列；浏览器预览使用单独存储，非正式应用数据。
- `src/components/`：任务行、原位编辑、象限布局与拖放展示。
- `src-tauri/src/storage.rs`：本机 SQLite、事务写入、结构校验、故障报告。
- `src-tauri/src/automation.rs`：CLI 参数、MCP 协议与工具适配，调用原生存储层。
- `src-tauri/src/lib.rs`：窗口生命周期、外部 revision 观察、关闭前等待编辑提交与保存完成。

正式数据位于 macOS Application Support 下的应用专用目录，使用 SQLite 完整同步事务；不依赖浏览器缓存、服务器或网络。

## 外部任务接口与跨进程存储

`main.rs` 在启动 Tauri 前识别 `--cli` / `--mcp`，交给 `automation.rs` 无窗口执行，避免已有 GUI 单实例吞掉调用。两个适配入口共用任务动作，写入只能调用 `storage.rs::commit_external`；MCP 不监听网络端口。工具契约与调用示例见 [CODEX.md](CODEX.md)。

数据流为 `CLI/MCP → automation → storage → SQLite`，GUI 为 `components → store/queue → Tauri command → storage → SQLite`。任务标题、ID 与象限的原生校验集中在存储层；前端领域规则用于交互与预览。外部请求拒绝不存在的修改/删除目标和内容冲突的重复 ID，GUI 继续容忍删除后的迟到编辑。

正式存储仍是 `task_document(id=1, version, content)` 与 `task_revision(id=1, revision)` 两张表，任务包含 id/title/completed/quadrant；本次接口没有增加表或迁移任务格式。写入在 IMMEDIATE 事务中先取得写锁，再读取最新任务并合并字段；读取任务和 revision 使用同一个读事务，避免跨进程提交时拼出不一致的快照。

GUI 对自身提交立即广播；原生观察线程每 750 ms 读取快照，只在 revision 变化时向主窗口广播。前端拒绝迟到 revision，并把未提交意图叠加到新快照。窗口隐藏和退出仍由原有编辑提交与队列确认流程负责；无窗口 CLI/MCP 进程在提交完成后返回结果。

常驻秘书的意图理解和长期规则属于外部调用方，不由应用自行识别或监控聊天。应用只接受明确的任务操作，不提供日期提醒或云同步。

## 悬浮小组件 · 2026-10-09

编码前完整阅读已安装 frontend-design 与 feature-architecture Skill，并核对 Tauri 官方窗口、事件、window-state 文档。

第一遍方案：像摆在桌角的一张小型任务纸，380×360，最小 340×300。仅顶部 44px 可拖动标题与三个轻线图标，下方平衡的 2×2 网格。文字左对齐，标题 11px/18px、任务 12px/19px，英文 Geist、中文系统苹方，数字沿用同一家族的 tabular-nums，不额外引入等宽标签。背景纸白 #F8F7F4，文字 #242521，次级灰 #8B8D88，线 #E3E2DD，悬停 #F2F1ED；小色点使用陶土 #A66C60、鼠尾草 #708474、琥珀 #A18857、灰 #98968C。深色用暖石墨，颜色仅用于定位标记。使用原生窗口圆角及阴影，不用透明毛玻璃。

```
┌ 四格图标 四象限          图钉 打开 隐藏 ┐
│ · 重要且紧急 2    │ · 重要不紧急 1     │
│ ○ 核对交付清单   │ ○ Read & reflect  │
│              +  │               +  │
├─────────────────┼──────────────────┤
│ · 紧急不重要 1   │ · 不重要不紧急 0   │
│ ○ 回复邮件       │ 暂无任务           │
│              +  │               +  │
└─────────────────┴──────────────────┘
```

编码前复审：暖白、四格均为用户明确要求。避免把每格包装成独立卡片；四格共用连续纸面，仅中央分割。任务数量只表示未完成件数，不加入统计。新增入口置于格子底部，任务完成圆圈提供足够点击范围；编辑任务复用原位输入，删除仅悬停出现，小组件不放拖动排序手柄。长标题最多两行，各格独立细滚动条，标题与新增入口固定。默认普通层级，图钉由用户选择置顶；状态用一枚小点与颜色表示，避免多余文字。

动效响应用户操作，140–180ms，完成态淡化与删除线，窗口显示/隐藏使用轻淡出并尊重 reduced-motion。任何保存错误必须可见且可重试。主窗口增加唯一的小组件入口，原生窗口菜单同步提供入口，不另建导航。

架构落位：领域模块定义任务变更；前端 store 负责乐观显示、待提交变更队列和原生事件接收；Rust 存储层在单个 SQLite 事务中把字段变更合并到最新文档，发出带递增 revision 的快照。不让两个窗口分别写完整旧快照。窗口创建、置顶、隐藏、状态恢复与退出协调由原生窗口模块负责。退出须等待所有窗口提交当前编辑并确认保存。

官方参考： https://v2.tauri.app/plugin/window-state/ 、 https://v2.tauri.app/reference/javascript/api/namespaceevent/ 、 https://v2.tauri.app/reference/config/ 。

### 截图复查与有针对性的迭代

第一轮检查 380×360 浅色与 340×300 深色：四格比例均衡、中央分割克制、标题和数量没有挤压。优化正文从 12.5px 到 13px、标题从 11.5px 到 12px，保持正文 20px 行高；深色完成态提升至 #85897E，避免已完成项过度沉入背景。截图改为等待任务文字的主题颜色过渡完成后采集，避免把过渡中间帧当成最终深色效果。第二轮 WebKit 六项检查通过，复查浅色、深色、最小窗口、空状态与 80 条长列表，保留单片纸面结构和低调的底部加号。

## 思维导图 · 1.3.0（2026-10-28）

编码前使用 feature-architecture 与 frontend-design，保留现有色板（纸白 #F8F7F4、墨灰 #30312F、次级灰 #777973、细线 #DEDED7、鼠尾草 #708474）及 Geist / 系统中文字体。任务行只增加一个 16px 细线导图图标，小组件为 14px；已有关联沿用象限强调色，未关联为淡灰。标题仍原位改名，不增加导航或设置。

方案复审：不增加任务详情页、整行装饰和常驻按钮文案。首次点击只出现窄幅原生 HTML dialog，任务名左对齐，下方“新建思维导图”“关联已有导图”，支持 Escape 与关闭。已有关联直接打开，文件丢失时可重新关联。

关联保存于 SQLite 独立 task_mindmaps 表，v1 任务 JSON 保持不变，避免旧 CLI/MCP 写入丢失关联。任务、关联、revision 在同一读事务中构成快照；关联在 IMMEDIATE 事务中确认任务存在并递增 revision。删除触发器只清除关联，不删除文件，对旧进程更新任务 JSON 同样生效。两个窗口复用 MindmapButton 和原生命令适配，窗口关闭/退出的等待屏障包含导图操作。

Rust mindmaps.rs 负责原生 .xmind ZIP 文件、新建失败清理、文件选择和唤起 Xmind；storage.rs 负责关联事务。新建目录为系统 Documents/四象限导图，标题清理后加 UUID 命名，不依赖任务标题作为关联键。并发新建只保留事务选中的一个新文件；重复点击不会覆盖已有文件。关联已有导图保留原文件位置。导图内容由 Xmind 编辑、保存，四象限只创建初始中心主题和记录文件位置。

文件结构参考 Xmind 官方 SDK： https://github.com/xmindltd/xmind-sdk-js/blob/master/src/utils/zipper.ts ，原生选择器使用 Tauri dialog： https://v2.tauri.app/plugin/dialog/ 。


实际复查使用 Xmind 26.05.01106。根据其本地保存结果，新建包声明 dataStructureVersion=3、layoutEngineVersion=5，解决首次保存出现旧格式转换提示的问题；实际新建、编辑、Cmd+S、关闭文件后再次打开通过。最小 340×300 小组件及 620×440 主窗口、浅色与深色均已截图复查，导图弹窗不溢出，任务标题与小图标保持可辨。截图为隔离浏览器数据，见 screenshots/mindmap-*.png。


## 集中导图入口 · 1.3.1（2026-10-28）

按 feature-architecture 与 frontend-design 复审，沿用纸白/石墨底、墨灰正文、细线和象限强调色、Geist/系统中文字体。主窗口与小组件均只在标题栏右上角保留一个 16px 导图按钮，任务行移除该按钮。单击标题或任务行空白选中任务，以淡底色和左侧 2px 象限色标记；双击标题、Enter 或 F2 原位改名。未选任务时按钮置灰，提示先选中任务；已有选中项时按钮提示中包含目标任务名称。

编码前复审保留 2×2 矩阵，不加入选中项详情、常驻说明或额外工具条。任务名因此获得更多横向空间。主窗口右上角使用同一个 flex 操作组排列导图和小组件按钮，避免旧的绝对定位规则将按钮分散。

TaskSelectionProvider 仅管理窗口内的临时选择状态，通过选中 ID 从当前快照解析任务；删除任务后清除选择，改名/换象限后保持选择。主窗口与小组件各自拥有 React context，不同步选择、不写 SQLite。两个标题栏复用 MindmapButton；切换任务时清除旧任务弹窗与错误，仍按选中任务的精确 ID 调用既有原生命令。新建、关联、再次打开与保存/退出屏障沿用 1.3.0 行为。

复查结果：修正旧标题栏绝对定位规则冲突后，主窗口和小组件的导图入口均位于右上角；最小尺寸下选择高亮、正文和标题栏按钮可辨。深浅色预览截图见 screenshots/mindmap-*-selected-*.png。
